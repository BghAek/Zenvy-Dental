# S4-7 Polish pass for Owner App

## What
Implemented all `[A]` (frontend) rows from the S4-7 copy and polish review for `apps/owner`:
- Swapped native `<select>` for `@zenvy/ui` `Select` component in `OnboardingPage`.
- Formatted `scheduledCallAt` inputs correctly to local timezone for the datetime-local HTML inputs in `OnboardingPage`.
- Translated `STATUS_LABELS` and `SEVERITY_LABELS` to French ("En attente", "Erreur", etc.).
- Improved layout, color tokens (`bg-card`, `text-foreground`, `text-muted-foreground`), and responsive styles in `SupportThreadsPage`, `ClientsPage`, and `OwnerLayout` to remove hardcoded Tailwind grays and align with the design system.
- Fixed keyboard accessibility on `TableRow`s (e.g. `ErrorsPage`) with `role="button"`, `tabIndex={0}`, and `onKeyDown`.
- Replaced hand-rolled error modals with the `Dialog` primitive from `@zenvy/ui` (and implemented it using `@radix-ui` in the shared ui package).
- Ensured all React Query `useQuery` / `useMutation` patterns have error handling (`isError`, `onError`), providing a user-facing retry CTA when loading fails (e.g. empty states mapping to "Impossible de charger...").

## Why & decisions
- **Dialogs**: Following the feedback to eliminate focus traps and lack of escape keys, the Radix UI Dialog primitive was incorporated into `@zenvy/ui` and is now used to render accessible modals with correct `aria` roles.
- **Error States**: Mapped missing `isError` flags in queries to display clear error messages with a `refetch` fallback. Mutations similarly now display inline error feedback on failures.
- **Tokens**: `OwnerLayout` and corresponding pages now map correctly to design-system tokens rather than loose color palettes, keeping a premium cohesive UI consistent with the main clinic web app.

## How to test
1. Run `pnpm dev` and navigate to the Owner portal.
2. Simulate a network error (DevTools > Network > Offline) on the `OnboardingPage`, `ErrorsPage`, or `SupportThreadsPage` to observe the new error states and retry buttons.
3. Open an Error or Onboarding item to verify the new accessible Modal dialog opens, locks background scroll, traps focus correctly, and can be dismissed using `Esc` or clicking the backdrop.
4. Attempt to mutate (edit status, send support reply) with an offline connection to verify the mutation `onError` block renders the red error feedback successfully.
